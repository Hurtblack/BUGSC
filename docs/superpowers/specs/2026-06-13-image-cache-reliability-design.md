# 资讯图片缓存与加载可靠性设计

> 日期：2026-06-13
> 关联代码：`ImageLoader`、`NewsFragment`

## 1. 问题

当前通用 `ImageLoader` 只使用 20MB 内存缓存。应用进程重启、内存缓存被回收或页面首次打开时，
所有资讯缩略图都需要重新下载；单次网络请求失败后也不会重试，因此图片会保持空白，只有手动刷新页面
触发新请求后才可能显示。

## 2. 目标

- 图片下载成功后写入应用缓存目录，后续进入页面优先从磁盘读取。
- 磁盘缓存有效期为 7 天，总容量上限为 50MB。
- 网络瞬时失败时自动重试一次，不要求用户手动刷新。
- 保留现有 20MB 内存缓存和 ImageView URL tag 防错位机制。
- 继续由资讯、市场和每日 WB 共用同一个图片加载器。

## 3. 设计

新增纯 Kotlin `ImageDiskCache`，使用图片 URL 的 SHA-256 作为文件名。读取时检查文件年龄，
过期文件立即删除；命中后更新文件修改时间，作为 LRU 访问时间。写入时先写临时文件，再重命名为
正式缓存文件，避免进程中断留下半文件。每次成功写入后按最久未访问顺序清理，直到总大小不超过 50MB。

`ImageLoader` 的加载顺序调整为：

1. 查询 20MB 内存缓存。
2. 在 IO 线程查询磁盘缓存并解码。
3. 磁盘未命中时请求网络；请求失败自动重试一次。
4. 下载成功后先写磁盘缓存，再解码并写入内存缓存。
5. 返回主线程前继续校验 ImageView tag，避免异步结果绑定到错误图片。

## 4. 错误处理

- 磁盘读取、写入和清理失败均视为缓存未命中，不阻断网络加载。
- HTTP 非 2xx、连接异常、读取异常和无法解码图片均视为本次尝试失败。
- 两次网络尝试都失败后保留当前占位背景，不抛出到 UI。
- 空 URL 不创建请求或缓存文件。

## 5. 测试

JVM 单元测试覆盖：

- 写入后可跨缓存实例读取，证明缓存不是仅存在于内存。
- 超过 7 天的文件无法读取并被删除。
- 超过 50MB 时优先淘汰最久未访问的文件。
- 第一次请求失败、第二次成功时返回成功结果且调用两次。
- 两次请求均失败时返回空结果且只调用两次。

## 6. 不做

- 不引入 Glide、Coil 等新依赖。
- 不增加 UI 刷新按钮或改变资讯列表布局。
- 不对服务端图片做格式转换或尺寸裁剪。
