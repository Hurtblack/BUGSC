# 聊天资料卡与消息气泡设计

## 目标

在一对一聊天页顶部展示交易对方的完整公开资料，并优化消息气泡的身份、时间和方向层级。资料必须通过 `/member/user/get-public?id=...` 获取，不能继续使用订单列表中可能脱敏的昵称。

## 顶部资料卡

采用已确认的紧凑方案 A：

- 左侧显示 52dp 圆形头像；无头像时显示昵称首字符。
- 右侧第一行显示完整昵称，第二行显示在线状态。
- 下方信息区显示 `交易时间：09:00 - 16:00（每天）UTC+8`。
- 联系方式显示 `联系方式：具体内容`，点击整行复制。
- 后台未公开联系方式时显示 `联系方式：未公开`，且不可复制。
- 公开资料加载失败时保留导航参数中的昵称，并显示“交易资料加载失败”，不影响聊天收发。

交易日数组顺序为周一到周日。全开显示“每天”，部分开启显示具体星期，全部关闭显示“未设置”。时区暂按 SCM 市场现有展示规则显示 UTC+8。

## 消息气泡

- 对方消息左对齐，显示 30dp 头像、完整昵称、深色圆角气泡和消息时间。
- 自己消息右对齐，使用青色圆角气泡，底部显示消息时间。
- 历史消息使用接口的 `createTime`；实时收到的消息同样使用消息字段时间。
- 乐观发送消息使用本地当前时间并显示“已发送”。
- 连续消息暂不做头像合并，保持实现简单且身份明确。

## 数据与错误处理

新增公开用户资料模型和解析器，字段包含用户 ID、昵称、头像、在线状态、交易日、起止时间和联系方式。`ChatClient` 提供公开资料查询方法。

交易创建反馈继续区分：

- 首次成功：显示“交易创建成功”和交易编号。
- 已存在：显示“该订单已有进行中的交易，无需重复创建”和已有交易编号。

实机已经确认 `JYDD202606151642351` 于 2026-06-15 16:42:35 创建成功，重复提交被正确拦截。

## 验证

- 单测覆盖公开资料解析、交易时间格式、联系方式回退和消息时间格式。
- Debug 构建与全量单测通过。
- 实机检查完整昵称、头像、资料卡、复制联系方式和左右消息气泡。
